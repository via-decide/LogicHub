Sensor Calibration + Health Evidence

Convert sensors from “connected parts” into trusted production instruments. Every IMU, encoder, camera, LiDAR, microscope stage, RF chain, temperature probe, current sensor, voltage divider, docking marker, and process sensor must prove that it is present, oriented, calibrated, fresh, and believable before the product can act on it.

1. Tool purpose

Sensor Calibration + Health Evidence is the production discipline for making hardware perception trustworthy. A sensor is not accepted just because it returns numbers. It must pass identity, wiring, range, noise, orientation, timing, calibration, drift, and field-health checks.

This tool turns bring-up into evidence: each product stores a repeatable calibration_receipt.json showing what sensor was tested, under what fixture, with which firmware/software revision, what raw values were observed, what offsets were computed, and whether the result is safe to use.

Detect sensor→Verify identity→Capture raw baseline→Check noise/range→Compute calibration→Write receipt→Runtime health monitor
Production rule: a sensor that has no calibration evidence must not be used for safety, navigation, measurement claims, payment, medical/lab decisions, motor arming, or automated process control.

6. Universal calibration checklist

Before calibration

  • Record product ID, revision, firmware hash, software hash, fixture ID, operator, timestamp, and ambient conditions.
  • Confirm power rails are stable and within tolerance before trusting any sensor reading.
  • Confirm the sensor is the correct part number and not an electrical substitute with different scale/orientation.
  • Confirm the mechanical mounting direction, connector keying, cable route, strain relief, and service access.

During calibration

  • Capture raw values before filtering so future debugging can separate hardware faults from software filters.
  • Measure noise and outliers over a fixed sample window.
  • Run a known physical stimulus: gravity, rotation, distance target, optical target, RF test signal, heater setpoint, current load, or motion command.
  • Write calibration constants only after read-back verification and receipt creation.

After calibration

  • Reboot or power-cycle and verify the calibration loads correctly.
  • Run a short runtime health test with stale-data detection enabled.
  • Store a human-readable summary and machine-readable JSON receipt.
  • Mark the unit blocked if the receipt is missing, partial, manually edited, or outside tolerance.

Field service

  • Compare live drift against factory baseline.
  • Recalibrate only through the same evidence path, not by changing constants silently.
  • Expose degraded states on local UI and logs.
  • Prevent automatic operation when critical sensors are stale or implausible.

9. Example calibration routines

Generic embedded sensor health loop

sensor_state = INIT
while true:
    sample = read_sensor_with_timeout()

    if sample.timeout:
        fault("SENSOR_STALE")
        enter_safe_state()
        continue

    if not sample.within_physical_limits():
        fault("SENSOR_IMPLAUSIBLE")
        enter_safe_state()
        continue

    update_noise_window(sample)
    if noise_window.outlier_rate > MAX_OUTLIER_RATE:
        fault("SENSOR_NOISY")
        enter_degraded_mode()
        continue

    publish_fresh_sample(sample, timestamp=monotonic_ms())

13. Output checklist for generated products

  • Design output: sensor placement drawing, orientation note, bus address, expected range, fault code list.
  • Firmware output: timeout, freshness counter, raw diagnostic path, safe-state transition.
  • Software output: calibration script, fixture runner, validation report renderer, local dashboard health state.
  • Manufacturing output: serialized calibration receipt and operator test procedure.
  • Field output: recalibration workflow, degraded-state visibility, service comparison against factory baseline.
Done state: the unit has no hidden sensor assumptions. Every sensor that affects control, safety, quality, measurement, or product claims has evidence.
