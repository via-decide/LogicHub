Tactile Determinism / Input FSM

Convert every physical input — button, rotary encoder, E-stop monitor, cartridge detect, limit switch, mode selector, guard switch, or dock sensor — into one clean, intentional, testable event.

Buttons Rotary encoders Switches Cartridge detect Endstops E-stop monitor Deterministic FSM

Purpose

A usable hardware product must not double-click, miss presses, react late, arm accidentally, or treat electrical noise as user intent. This tool defines the input architecture that turns physical contact into stable semantic events.

Output: input map, debounce policy, event queue, state machine, pass/fail test receipt, and risk ledger for every physical input.

Use when

Any product has a user-facing control, service button, cartridge switch, guard sensor, endstop, docking input, rotary encoder, or motor-enable control.

Do not use software debounce as the only safety mechanism. E-stop, motor power, heater cutoff, mains isolation, and high-force machines need independent hardware safety paths.

1. Production rule

Physical contact is not an event. A physical contact is noisy evidence. An event is emitted only after the input is electrically valid, time-stable, state-legal, and safe for the current operating mode.

contact transition → electrical filter → timestamp → debounce window → FSM transition → semantic event → action gate

3. Canonical FSM

IDLEStable inactive
PRESS_CANDIDATEFirst edge seen
PRESSEDDebounce passed
LONG_HELDHold threshold
RELEASE_CANDIDATERelease edge seen
EVENT_EMITTEDOne action only
Rule: interrupt handlers should capture time and raw state only. Heavy work, flash writes, motor commands, network calls, display updates, and file writes belong outside the ISR.

4. Electrical pattern

Active-low button input

VCC ── 10k pull-up ── MCU GPIO
                   │
                switch
                   │
                  GND

Optional: 100nF to GND near MCU input
Better: Schmitt input / RC + Schmitt for noisy cables

Use internal pull-ups only for short, local buttons. Use external pull-up, RC filtering, ESD/TVS, and shielded routing for external panels or cables.

Rotary encoder input

A ── pull-up/filter ── GPIO interrupt-capable
B ── pull-up/filter ── GPIO interrupt-capable
SW ─ pull-up/filter ── GPIO
GND common, cable short or shielded

Decode with a legal quadrature transition table. Reject illegal state jumps instead of adding false steps.

E-stop boundary: the emergency stop path must physically interrupt hazardous energy or command an independent safety-rated cutoff. Software may display or log E-stop state, but must not be the only stop mechanism.

5. Firmware architecture pattern

ISR / GPIO callback:
  raw = read_gpio(pin)
  now = monotonic_us()
  input_queue.push({pin, raw, now})

Input service loop:
  event = debounce_fsm.consume(raw_sample)
  if event:
      semantic_event = map_to_command(event)
      if mode_gate.allows(semantic_event):
          action_queue.push(semantic_event)
      else:
          fault_log.record_rejected_event(semantic_event)

Debounce window

Start with 10–30 ms for tactile switches. Measure real hardware and store the chosen value in the input manifest.

Hold threshold

Use separate thresholds for short press, long press, and service hold. Do not overload one button with hidden destructive actions.

Event IDs

Emit semantic events such as CARTRIDGE_VERIFY_REQUESTED, not raw pin changes.

8. Checklist

Hardware checklist

  • Pull state defined: every input has a known default through pull-up/pull-down.
  • Voltage safe: input voltage never exceeds MCU absolute maximum.
  • Connector safe: external buttons/switches have ESD and cable-noise consideration.
  • Safety separation: hazardous stop paths are not software-only.
  • Labelled interface: panel, connector, or harness clearly maps to input function.

Firmware checklist

  • ISR minimal: no display, flash, motor, or network work inside interrupt.
  • Event queue: raw samples and semantic actions are separated.
  • Debounce measured: policy is documented per input class.
  • Mode-gated: events are legal only in defined system states.
  • Fault visible: stuck input, impossible sequence, and timeout produce readable faults.

12. Minimal firmware pseudocode

enum InputState { IDLE, PRESS_CANDIDATE, PRESSED, LONG_HELD, RELEASE_CANDIDATE };

void input_tick(Input *in, bool raw, uint32_t now_ms) {
  switch (in->state) {
    case IDLE:
      if (raw == ACTIVE) { in->state = PRESS_CANDIDATE; in->t0 = now_ms; }
      break;
    case PRESS_CANDIDATE:
      if (raw != ACTIVE) in->state = IDLE;
      else if (now_ms - in->t0 >= in->debounce_ms) {
        in->state = PRESSED;
        in->pressed_at = now_ms;
      }
      break;
    case PRESSED:
      if (raw != ACTIVE) { in->state = RELEASE_CANDIDATE; in->t0 = now_ms; }
      else if (now_ms - in->pressed_at >= in->long_ms) {
        emit_event(in->long_event);
        in->state = LONG_HELD;
      }
      break;
    case RELEASE_CANDIDATE:
      if (raw == ACTIVE) in->state = PRESSED;
      else if (now_ms - in->t0 >= in->debounce_ms) {
        if (now_ms - in->pressed_at < in->long_ms) emit_event(in->short_event);
        in->state = IDLE;
      }
      break;
    case LONG_HELD:
      if (raw != ACTIVE) { in->state = RELEASE_CANDIDATE; in->t0 = now_ms; }
      break;
  }
}
