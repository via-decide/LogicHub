Universal Hardware Production Tool · T01

Power Standardization & Protection

Design pattern for hardware that “just works” when powered: protected inputs, known rails, current budget, safe brownout behaviour, and clear production gates before any user or supplier touches the device.

USB-C power Battery input Reverse-polarity protection Fuse / PTC TVS / ESD Power tree Brownout Derating
PURPOSE

Make every board, module, robot, charger, camera, printer, and machine accept power safely without requiring the user to understand voltage, polarity, rail sequencing, or current limits.

USE WHEN

A project has USB-C, barrel jack, battery, external PSU, motor power, heater power, Raspberry Pi/SBC input, camera rails, flash rails, sensors, relays, or field wiring.

BLOCKER

No prototype should be powered until input voltage range, fuse/limit device, reverse protection, rail budget, brownout state, and first-power test procedure are documented.

1. Design model

SOURCE → ENTRY → INTENT → STATE/LOGIC → ACTIONS → OUTPUT/METRICS

LayerT01 meaning
SOURCEUSB-C receptacle, DC jack, battery pack, bench PSU, EVSE supply, solar/battery system, robot pack, machine mains input.
ENTRYConnector, fuse/PTC, reverse-protection MOSFET/diode, TVS, ESD, EMI filter, ideal diode, power switch.
INTENTPower the system safely while rejecting wrong polarity, overcurrent, overvoltage, ESD, brownout, and unsafe plug/unplug states.
STATE/LOGICRails good, rails bad, brownout, overload, thermal throttle, battery low, charger connected, USB-only, external PSU, service mode.
ACTIONSEnable regulator, latch fault, reset MCU, cut motor/heater relay, show status, log event, block write/commit, enter safe mode.
OUTPUT/METRICSMeasured rail voltage, ripple, current, temperature, inrush, reset count, runtime, fuse trip margin, pass/fail receipt.

Default rule

Every hardware product needs one written power contract. The contract defines acceptable inputs, protected paths, rail sequence, maximum current, thermal margin, brownout behaviour, and what the user sees when power is wrong.

3. Production-stage map

Stage 0
Input contract freeze.
Define exact power sources: USB-C 5V only, USB-C PD, battery, 12V/24V DC, mains-derived PSU, PoE, solar/battery, bench-only.
Stage 1
Protection topology.
Choose fuse/PTC, reverse-polarity method, TVS/ESD, connector rating, switch, ideal diode, soft-start/inrush control.
Stage 2
Rail architecture.
Map all rails, regulator efficiency, dropout, sequencing, always-on rail, switched rail, analog/digital/noisy-motor separation.
Stage 3
Load budget.
List every load with idle, typical, peak, startup/inrush, stall, heater max, RF peak, camera peak, motor transient.
Stage 4
Brownout and fault policy.
Define what shuts down first, what logs, what remains powered, and what the user sees.
Stage 5
Layout and wiring release.
Validate trace width, copper, connector current rating, creepage/clearance where relevant, star ground, motor/heater separation.
Stage 6
First-power procedure.
Power with current-limited bench supply, no expensive modules inserted, record rail voltages and thermal rise.
Stage 7
Evidence receipt.
Save measured voltages, currents, temperatures, pass/fail gates, photos, instrument IDs, operator, date, revision.

4. Design checklist

Electrical checklist

  • Input connector current and voltage rating confirmed.
  • Fuse/PTC/eFuse sized below wire/trace/connector damage limit.
  • Reverse-polarity path tested, not only simulated.
  • TVS/ESD part placed close to connector.
  • All rails have expected load, regulator margin, and test points.
  • Motor/heater/noisy loads separated from MCU/sensor rails.
  • Brownout threshold is above flash-write corruption region.
  • Thermal rise measured at worst expected load.

User/product checklist

  • User cannot plug power backward or into the wrong connector without protection.
  • Power error shows a visible state: LED/OLED/buzzer/log.
  • No exposed live/mains terminals in user-accessible areas.
  • Battery projects include fuse, disconnect, charger boundary, and low-voltage handling.
  • Outdoor products include weatherproofing, grounding, strain relief, and service access.
  • High-power products include physical emergency cutoff and inspection checklist.
  • Every production unit produces a power validation receipt.

5. Pass/fail gates

GatePass conditionFail condition
Input identityConnector, voltage range, current limit, polarity, and source type are documented.“5V/12V/24V” is stated without tolerance, source, connector, or limit.
ProtectionFuse/eFuse/PTC and reverse-polarity protection are present and rated.Protection omitted to save cost or assumed inside user adapter.
Rail budgetEvery load has idle/typical/peak/startup values and regulator margin.Only MCU current is counted; motors, heaters, radios, cameras, and LEDs ignored.
BrownoutDevice enters safe state before corrupting storage or driving actuators unpredictably.MCU resets randomly, flash writes during droop, or actuator remains enabled.
ThermalWorst-case current test passes with enclosure closed or with defined airflow.Only open-bench thermal test done; no enclosure or hot-environment margin.
EvidenceMeasured voltages/current/temperature recorded with date, unit ID, operator, and revision.No repeatable test receipt exists.

7. Example wiring and logic patterns

Low-voltage USB-C 5V-only input

USB-C Receptacle
  VBUS ── Fuse/eFuse ── Reverse/ideal diode ── TVS ── 5V_SYS
  CC1 ── 5.1kΩ ── GND
  CC2 ── 5.1kΩ ── GND
  GND ─────────────────────────────────────── GND

5V_SYS ── Buck/LDO ── 3V3_SYS
3V3_SYS ── MCU / Flash / Sensors

Required tests:
- plug orientation A/B
- no-load voltage
- max-load voltage
- inrush
- brownout reset
- thermal rise

Use for low-voltage prototypes such as cartridge readers, OpenMV accessories, small displays, and microcontroller boards. USB-C PD negotiation is a separate design path; do not imply PD without a PD controller.

Firmware power-fault policy

BOOT:
  read rail_adc
  if rail_adc < SAFE_BOOT_MIN:
      show("POWER LOW")
      disable_actuators()
      block_flash_writes()
      wait_or_reset()

RUN:
  every 100 ms:
      sample rails, temp, current
      if brownout_warning:
          stop new transactions
          save small fault marker only if safe
          show amber fault
      if critical_fault:
          disable motors/heaters/relays
          show red fault
          require user reset

FLASH WRITE:
  require rail_good_for_write == true
  require reserve_energy_or_stable_input == true
  write staging
  verify hash
  commit manifest pointer

Use for 8MB cartridge, drone blackbox, RISC-V image/config updates, OpenEVSE config, and any local-first hardware that must not corrupt state.
