1. Tool purpose

Source Manifest + BOM/CAD Hash Intake is the production-control layer that prevents random files, stale forks, edited CAD, mixed licenses, unpinned firmware, and undocumented vendor blobs from entering the build.

The tool creates one canonical ledger for every input: source URL, repository, commit or release, file path, file type, owner, license, checksum, production role, and approval status.

Find source→Classify artifact→Preserve bytes→Hash file→Record license→Map to BOM/CAD/firmware→Approve or block

This tool is used before fabrication, flashing, purchasing, supplier handoff, grant/demo submission, safety review, or LogicHub/GN8R task execution.

2. When to use this tool

Open-source project intake

Use when importing FarmBot, Voron, OpenFlexure, OpenEVSE, SatNOGS, OpenMV/OpenIPC, or any external ecosystem into your build plan.

Start here

CAD/BOM freeze

Use before ordering parts, cutting panels, printing enclosures, making PCBs, or sending files to suppliers.

Pre-fabrication

Firmware/image release

Use before flashing firmware, Linux images, FPGA bitstreams, camera firmware, SD-card images, or microcontroller binaries.

Do not skip

License review

Use when assets include mixed licenses, GPL, MIT, Apache-2.0, CERN-OHL, Creative Commons, proprietary blobs, datasheets, or vendor examples.

Revision comparison

Use when deciding whether two builds are identical, whether a supplier changed a file, or whether a fork has diverged from upstream.

Evidence receipt

Use after validation so every test receipt can point back to the exact BOM, CAD, firmware, config, and machine revision tested.

6. Clean checklist

  • Use official upstream first; forks are allowed only when explicitly justified.
  • Record whether an artifact is upstream, generated, modified, vendor, datasheet, or local analysis.
  • Preserve original filenames and add canonical IDs separately.
  • Hash every file using SHA-256 before editing.
  • Keep generated outputs separate from source files.
  • Do not mix CAD versions, BOM versions, and firmware versions without a compatibility note.
  • Never send unreviewed generated Gerbers, STEP, STL, or firmware binaries to production.
  • Do not claim open-source commercial freedom until the file-level license inventory is complete.
  • Record all blocked files: missing license, binary-only, unsafe, stale, unsupported, or unverified.
  • Attach validation receipts to the exact manifest ID that was tested.

10. Minimal hashing commands

Use these commands only on files you are legally allowed to store locally. Keep raw intake files read-only after hashing.

# Linux/macOS: create SHA-256 manifest
find raw_intake -type f -print0 | sort -z | xargs -0 shasum -a 256 > file_hashes.sha256

# Python fallback: deterministic CSV manifest
python3 - <<'PY'
from pathlib import Path
import hashlib, csv
root = Path('raw_intake')
rows = []
for p in sorted(root.rglob('*')):
    if p.is_file():
        rows.append({
            'path': str(p),
            'size_bytes': p.stat().st_size,
            'sha256': hashlib.sha256(p.read_bytes()).hexdigest()
        })
with open('file_hashes.csv','w',newline='') as f:
    w = csv.DictWriter(f, fieldnames=['path','size_bytes','sha256'])
    w.writeheader(); w.writerows(rows)
PY

12. Production rule

A project is not production-ready because files exist. It becomes production-controllable only when every source file, generated file, BOM item, CAD part, firmware image, configuration, and validation receipt can be traced back to a versioned manifest.

Default decision: if the file cannot be traced, hashed, regenerated, licensed, or safety-reviewed, it is not part of the release.
